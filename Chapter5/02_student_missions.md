# PyMySQL 偵探教室：消失的黃金吐司

## 案情

2026 年 8 月 20 日 21:25，保全發現珍貴的「黃金吐司」從二樓保管庫 R03 消失。系統沒有遭到外部入侵，因此犯人極可能就在十名關係人之中。門禁初步顯示，當晚共有六人成功進入 R03；學生必須先重建整晚時間線，再從案發區間與其他證據逐步排除無關訪客。

你的任務不是猜答案，而是用 SQL 查出證據。每一關都要保留：SQL、查詢結果、你的推論。

## 規則

- 只能依資料庫中的紀錄推理。
- `DENIED` 表示門禁失敗，不能視為進入房間。
- 監視器辨識有 `confidence`，數字越接近 1 越可信。
- 刪除訊息並未真的消失，鑑識人員已復原在 `messages` 表中。

## 任務卡

### 第一關：熟悉案情（SELECT）

1. 查詢 `case_brief`。
2. 列出所有房間的名稱與樓層。
3. 列出十名關係人的姓名、職業與訪談說法。

### 第二關：重建整晚訪客名單（WHERE / BETWEEN / ORDER BY）

4. 找出 `2026-08-20 18:00:00` 到 `22:00:00` 的所有成功門禁紀錄，依時間排序。這是展覽開放與案發所在的同一個晚上。
5. 在上述晚間區間內，找出曾以 `IN + SUCCESS` 進入 R03 的人員編號；依進入時間排序，結果應為早川秋、洛伊德·佛傑、帕瓦、波奇塔、彭德與淀治六人。
6. 比較六人的進出時間與訪談說法；再把範圍縮到實際案發區間 `21:10:00` 到 `21:25:00`，哪些人仍需優先調查？

### 第三關：比對現場物證（條件組合）

7. 現場有四組足跡：波奇塔 12.0、帕瓦 23.5、彭德 27.5、淀治 27.5。查出四人的尺寸並依人員編號排序。
8. 現場另有橘色纖維與少量橘色短毛。查出具有橘色痕跡的人，結果應包含淀治、波奇塔、帕瓦與彭德。
9. 比較淀治的深橘帽 T、波奇塔的橘色本體、帕瓦的布質腕帶與彭德的南瓜圍巾，說明為何單靠橘色痕跡不能定案。

### 第四關：串連資料（JOIN）

10. 將 R03 的成功門禁紀錄與 `suspects` 連接，顯示姓名、職業、進出時間與動作。
11. 將案發區間的監視器紀錄與人員資料連接，顯示姓名、地點、衣著和攜帶物。
12. 誰曾購買監視器中出現的「銀色保溫袋」？請連接消費紀錄與人員資料。

### 第五關：數位鑑識（LIKE / JOIN / deleted flag）

13. 找出所有已刪除的訊息。
14. 搜尋內容包含「斷電」、「保溫袋」或「巡邏」的訊息，顯示寄件者與收件者姓名。
15. 誰曾試圖安排在案發前後進行斷電？對方是否同意？

### 最終關：寫出逮捕令（多表 JOIN 或子查詢）

16. 寫出一條 SQL，同時滿足以下條件，找出唯一嫌犯：
    - 足跡尺寸為 27.5。
    - 具有橘色痕跡，符合現場橘色纖維。
    - 在案發區間成功進入 R03。
    - 監視器拍到其攜帶銀色保溫袋。
    - 曾購買銀色保溫袋。
17. 提交一段 100 字內的結案報告，至少引用三種不同資料表的證據。
18. 說明吐司咬痕為何能排除波奇塔與彭德，但仍應以可重現的數位證據鏈作為主要結論。

## 加分挑戰

1. 用 `GROUP BY` 統計每人成功刷卡的次數，找出次數最多者。
2. 用 `LEFT JOIN` 找出完全沒有被監視器辨識到的人。
3. 使用 `%s` 參數化查詢，讓使用者輸入房間編號與起訖時間；禁止用 f-string 拼接 SQL。
4. 把最終查詢包成 Python 函式 `find_prime_suspect(connection)`。
